# 提示词包（可直接粘贴使用）

三份文本，用途不同：

| 编号 | 用途 | 注入位置 | 使用者 |
| --- | --- | --- | --- |
| **A** | 预防：把纪律变成硬约束 | system prompt（插件 M1 / 或写进 `AGENTS.md`） | 插件或用户手动 |
| **B** | 纠正：损坏已发生，当场重发 | 同一 turn 内注入的 steering 消息（插件 M4） | 插件自动 |
| **C** | 拒绝：把静默 no-op 变成显式失败 | `tools/pre-execute` 的 `deny.reason`（插件 M2） | 插件自动 |

写作原则：**短**。超长提示词会稀释注意力，与要解决的问题背道而驰。
且提示词本身**不书写完整字面闭合标签**（只说"以 `</` 开头的闭合标签"）——它自己必须示范这条纪律。

---

## A. 预防型（system prompt 规则块）

```
[工具调用结构纪律]

已知故障模式（当作硬约束，不是建议）：当单个工具参数（尤其 run_code 的 code、write 的
content）超过约 100 行，或参数内容本身包含大量以 "</" 开头的闭合标签（HTML/CSS/XML/
JSX/调用标记）时，你会在参数末尾丢失边界，表现为三种形态：
  ① 末端出现重复的结束序列（外层收尾标记连续出现多次）；
  ② 漏写开场标记，参数退化为普通正文；
  ③ 参数内容泄漏进 assistant 正文。
此时工具调用不会执行，且不报错——静默失败。它比报错危险得多，你必须主动防它。

硬规则：
1. 单次调用写入的源文本 ≤ 100 行；超过就分块：首块用 write，其余用追加（append/edit）。
2. 参数内容里不写完整的字面闭合标签：用拼接构造（"<" + "/style>"）或改写措辞避开。
3. 任何落盘操作后，必须用一次独立的小调用回读校验（行数 + 一个唯一标记）；
   未校验不得声称"已完成"。
4. 写文件优先用 write / edit 工具；不要在 run_code 里嵌超长字符串。
5. 单次调用的结束序列只允许出现一次，且必须是最后一个字符序列。
6. 一旦发现自己已出现上述任一形态：不要原样重试，立即改为更小的分块重发，
   并明确说明"上一次未执行"。
```

## B. 纠正型（检测到损坏后注入的 steering）

触发：M4 判定"本 step 的 assistant 输出含损坏的调用标记"（V1/V2/V3 任一）。
要点：**先否定"已成功"的错觉**，再给可执行的更小方案，并且**禁止复述损坏内容**。

```
[结构校验失败 · 自动纠正]

上一步的 assistant 输出被判为工具调用结构损坏（检测到未配对的调用标记、重复的结束序列，
或调用标记泄漏为正文）。该步**未执行任何操作**——不要假设它已成功，也不要引用它的结果。

现在请重新执行同一步骤，并遵守：
1. 把 payload 拆到每块 ≤ 100 行：首块用 write，其余用追加。
2. 参数里不要出现完整的字面闭合标签，用拼接构造。
3. 每块落盘后用一次独立的小调用回读校验。
4. 不要复述、不要重新输出上一段损坏内容——直接给出新的、更小的调用。
```

## C. 拒绝型（`deny.reason` / guard 返回值）

触发：M2 在 dispatch 前发现参数边界已损坏（V1 一类：结构尚可解析但明显带伤）。
要点：一句话说清"没执行 + 为什么 + 怎么改"。

```
参数结构校验失败：参数疑似边界丢失（检测到未配对的调用标记或重复的结束序列），本次未执行。
请拆成 ≤100 行的若干块，先写首块再用追加，并避免字面闭合标签。
```

## 使用说明

- **A 的安装**：两种都行——① 交给插件（M1，profile 生效、可配置、可关闭）；
  ② 手动追加到 `AGENTS.md`（立刻生效、无需装插件、但每次都占上下文预算）。
  建议先用 ① 的 M1，代价是每次请求多几百 token；A 已经是精简版，不要再加长。
- **B / C 不要手动使用**：它们由插件在检测命中时注入。手动注入会与自动注入重复。
- **可调参数**（插件 `Config`，与 `docs/INTERFACE.md` 的 `DEFAULT_CONFIG` 保持一致）：
  `enabled`、`maxLines`（默认 100）、`maxChars`（默认 20000）、`closingTagCount`（默认 8）、
  `endSequenceRepeats`（默认 2）、`maxCorrectionsPerTurn`（默认 1，防纠偏循环）、`lang`。
- **反面用法**：不要把这些规则扩写成几千字的长文；不要叠加互相矛盾的追加约束。
