# dsh-structured-output-guard

**简体中文** | [English](README.en.md)

一个 **DSH（DeepSeek Harness）宿主插件**：把**静默**的工具调用失败，变成**显式且可恢复**的失败。

它会检测损坏的工具调用参数、带可操作原因拦下这次调用；当 turn 被静默关闭时，让模型**在同一个 turn 内**重试。

> **状态**：当前可用。`M2`（拦截）与 `M4`（自愈）已在真实 profile 上**现场验证**；但并非所有设想都能实现，请务必读「已验证 / 未验证」与「已知边界」两节。

---

## 1. 问题

当模型要写一个非常大的工具调用参数时——尤其当内容本身就充满以 `</` 开头的闭合标签（HTML / CSS / XML / JSX）——它可能在生成过程中**丢掉参数的边界**。已观测到三种形态：

- **V1 结束序列增殖**：调用结尾的结束标记在尾部重复；
- **V2 开场标记缺失**：只剩参数开场标记，没有外层调用开场标记；
- **V3 泄漏为正文**：调用信封混进 assistant 的**正文**，没有被识别为真正的工具调用。

另外，泄漏出来的标记**不止一种方言**：既可能是裸标签（`<invoke` / `<parameter`），也可能是**带命名空间前缀**的（如 `<antml:invoke>` / `<antml:parameter>`）。后者曾在一次真实会话里让检测器**整体漏判**——因为 `<antml:parameter` 里根本没有 `<parameter` 这个子串。这就是缺陷 **D-10**，已修（见 §7.4）。

三种都**静默失败**：不执行、不报错，turn 正常关闭，流程上像是做完了。

还有第四种相关形态 **V4**：harness 的容错 JSON 解析把非法参数降级成 `{}`，工具于是带着空参数执行。

**更麻烦的是**：损坏输出会留在对话里，模型开始模仿自己那份坏格式，于是一次坏步骤很容易**自我复制**；而 compact **不会删掉这个样本**，只会压缩它周围的文本。

### 一个真实的（节选）例子

> 记号说明：`INVOKE_END` = 由 `<` + `/invoke` + `>` 组成的 token。这里刻意这样书写——**这个守卫存在的意义，就是不写连续的字面闭合标签**。

一次参数体很长、闭合标签很密的调用，尾部变成了这样（节选；原文里外层结束序列重复了**四组**）：

```
<parameter name="code">…一段很长的 JS…</parameter>
<parameter name="description">Read ui.html size and profile job output</parameter>
INVOKE_END × 4   ← 外层结束序列在此重复
```

那一步**一张工具卡都没产生**。agent 循环看到零个工具调用，直接返回 `{kind:'completed'}`，turn 就此关闭。**任何地方都没有报错。**

用户的体感是：模型像是在思考中途"停工"，输出质量持续下滑，而且后续每一轮都在重复同一种坏格式。

## 2. 装上之后的变化

| 以前 | 现在 |
| --- | --- |
| 坏的调用**不执行**、也**不报错**，看起来像成功了。 | 调用在**分发前被拦下**并给出可操作原因：「参数疑似边界丢失，**本次未执行**；请拆成 ≤100 行分块重发」——静默 no-op 变成显式失败。 |
| 信封泄漏成正文，这一步什么都没做，turn 却正常关闭。 | **turn 不关闭**，并注入一条纠正，让模型**在同一个 turn 内**重发。 |
| 写入类工具自报成功、其实什么都没改。 | 结果后面补一句：「工具自报未产生任何改动，请回读确认」。 |
| 坏样本留在历史里，持续被模仿。 | **没解决。** 在这版 harness 上插件改不了历史（见「已知边界」）。它缩短故障窗口，**不洗白过去**。绕法：新开会话，或用一句话让模型忽略那段损坏内容。 |

## 3. 它做什么（人话）

三个守卫，平时都不出声：

1. **拦截（M2）**——工具调用分发前扫描已解析的参数。若某个字符串参数的边界已损坏（尾部结束序列增殖，或结构中途被截断）**且**体量够大（≥2000 字符或 ≥20 行），就拒绝这次调用并说明该怎么改。它同时兜住 `{}` 那种情况：声明了必填参数的工具却收到空参数。
2. **纠偏（M3）**——**写入类**工具跑完后，检查是否有**机器可读**的空转证据（`noop: true`、`status: "noop"`、`written: 0` 且确实带了内容），有就补一句短提示。它**不**做自由文本猜测。
3. **自愈（M4）**——观察已提交的 assistant 消息。若某一步的输出损坏**且**该步**没有任何工具调用**，就在 turn 即将关闭的那一刻注入一条纠正，让 turn 保持打开、模型重发调用。§1 里那个例子，正是靠它。
   它是**两档有界**的：第一次给"上一步没执行 + 该怎么改"；如果紧接着那一步**还是**写坏（真实会话里确实发生过），再给一次**更硬更短**的指令——"这一步只发一个调用、参数不超过 40 行、不要解释"。上限由 `maxCorrectionsPerTurn` 控制（本 bundle 设为 `2`），到顶即停，不会循环。

**刻意没做**：**完全不注入提示词**（曾经实现过 system-prompt 规则块，后按设计决策**移除**——提示词层约束力不保证，且会分散 attention）；也不做"强制小块写入工具"。

## 4. 安装（DSH 用户）

用 Harness 自带的**插件管理器**安装。`install_bundle` 的 `target` 接受**绝对本地路径**、`file:` / `link:` 路径、**git spec**、或 tarball URL。**不要**手改 profile。

**方式 A · 克隆后本地安装（现在就能用，推荐）**

```bash
git clone https://github.com/IRwDONE/dsh-structured-output-guard.git
```

然后在插件管理器里执行 `install_bundle`，`target` 填**克隆目录下的 `plugin/` 绝对路径**：

```
<你的克隆路径>\dsh-structured-output-guard\plugin
```

⚠️ target 必须是**包目录**——也就是含 `package.json` 与 `cordis.patch.yml` 的那一层。

**方式 B · 一条命令直接用 GitHub 链接（目前不生效）**

```
https://github.com/IRwDONE/dsh-structured-output-guard
```

git spec 会按**仓库根**找包，而本仓库的包在 `plugin/` 子目录，所以这条**目前会失败**。等包挪到仓库根之后即可（这是可选改进，尚未做）。

**安装之后**

```
1. install_bundle 返回 application: "applied" -> 已生效
   若提示需要重启，就重启 Harness。
2. 确认该行已挂载：插件管理器里能看到它，或用 Harness 的 Config 检查。
3. 随时停用：插件管理器里禁用该 bundle；
   或把该行 config 的 enabled 设为 false（此时不注册任何监听器）。
```

**不需要**：构建步骤、任何运行时依赖、前端半边。这个 bundle 是纯 ESM JavaScript，只用 Node 内置模块（`node:fs`、`node:os`、`node:path`）。

## 5. 配置

该行的 `config` 会被**校验并归一化**；非法值**回退默认**而不是抛错。数值阈值必须是**整数且 ≥1**（只有 `maxCorrectionsPerTurn` 允许 `0`）。

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `enabled` | `true` | 为 `false` 时**不注册任何监听器**，等同关闭插件 |
| `maxLines` | `100` | 单个字符串叶子的行数上限（`PAYLOAD_TOO_LONG` 预警） |
| `maxChars` | `20000` | 单个字符串叶子的字符数上限 |
| `closingTagCount` | `8` | `</` 前缀出现多少次算「密集」——**只作证据**，永不导致拦截 |
| `endSequenceRepeats` | `2` | 尾部**连续**结束序列达到几个即判损坏 |
| `maxCorrectionsPerTurn` | `1` | 每个 turn 最多自愈几次（防循环）。**本 bundle 的 patch 把它设为 `2`**：让"第一次纠正后又写坏"的情况获得一次更硬的二次纠正 |
| `lang` | `zh` | `zh` / `en`，决定注入文案与拦截原因的语言 |
| `noopCheck` | `true` | `M3` 空转检查的总开关 |
| `debugLog` | `false` | 诊断日志开关；`false` 时不打开任何文件（零开销） |
| `debugLogPath` | `''` | 空串 ⇒ 由**系统临时目录**推导（绝不硬编码本机路径） |
| `contextGuard` | `false` | **内部保留、未接线**——见「已知边界」 |
| `contextGuardNote` | `''` | **内部保留、未接线** |

## 6. 已验证 / 未验证

验证刻意分两层：「代码是否符合契约」由自动化探针证明；「插件是否真的改变了真实对话」只在**亲眼观测到**的地方才算数。

| 结论 | 状态 | 证据 |
| --- | --- | --- |
| `M2` 真的拦住了损坏调用 | ✅ **现场观测** | 一次真实的、22 行以上且结构截断的参数在分发前被拒，并确认目标文件**未被创建** |
| `M4` 让 turn 不关闭并继续 | ✅ **现场观测** | 诊断日志完整链条：`damaged:true, silentFailure:true` → `turn-stopping` 命中记录 → `agent.inject()` 成功 → `agent/inbox/spliced` → **同一 turn 号内新开一步** |
| `M3` 只认显式证据 | ✅ 探针 | 独立探针；早先的自由文本启发式在真实会话误报 5 次后**已删除** |
| 检测器契约（形状、裁定、纯函数纪律） | ✅ 探针 | 独立 **480** 条检测器断言 + **102** 条接线断言，加作者测试台 **187** 条，**全绿** |
| `M1` 预防提示词 | ➖ **按设计移除** | 提示词层约束力不保证，且会分散 attention |
| `M5` 改写历史 | ❌ **本版做不到** | 见「已知边界」D-8 |
| 自愈能让模型**真正重做**丢失的工作 | ⚠️ **真实故障中观测到：没有** | 在一个真实用户会话里 M4 完整走通（检测 → 注入 → turn 未关闭、多跑一步），但**那一步又写坏了**（还把 23 KB 内容当正文吐出），随后限次用尽、turn 正常关闭。这正是**二次升级**的由来；而二次升级本身**尚未**在真实故障中被观测到 |

**怎么验的**：由**独立作者**编写的探针（`verify/probe.mjs`、`verify/probe-index.mjs`，**不复用**作者断言），外加一套带**前后哈希守护**的复现脚本（`verify/run-all.sh`）。

## 7. 技术细节

### 7.1 决定设计的两条 harness 事实

1. **DSH 里不存在文本协议的调用解析器。** 本版走 provider 原生 OpenAI 风格 `tool_calls`（经 `pi-ai`）。所以当模型把信封**当正文吐出**时，没有任何东西会把它变成调用：消息里零个 `tool-call` 块，agent 循环直接返回 `{kind:'completed'}`。**结论：那个场景下 `tools/pre-execute` 根本不会被触达，检测只能挂在 `session/event` 上。**
2. **`llm/stream` 收到的请求是冻结的。** `dsh-agent-loop` 组装完请求后把整个 envelope `Object.freeze`（并 deepFreeze 每条消息），才交给 `dsh-llm` 的 waterfall。所以监听器**无法**改写模型可见历史——这正是 `M5` 停用的直接原因。

### 7.2 接缝与纪律

| 机制 | 接缝 | 纪律 |
| --- | --- | --- |
| `M2` | `tools/pre-execute` waterfall `(exec, next)` | 要么拒绝，要么 `next()`，**绝不接管别人的决策** |
| `M3` | `tools/post-execute` waterfall `(exec, result, next)` | 先 `await next()`，然后**只做加法**（追加 `additionalContexts`） |
| `M4` 观察 | `session/event` → `assistant/message` | 只观察，**绝不干扰已提交的事件** |
| `M4` 纠正 | `agent/turn-stopping`（serial）+ `agent.inject()` | `inject` 把消息放进 `next-step` 且**不唤醒驱动**，这正是 turn 不关闭的原因 |

### 7.3 文档与证据

- `docs/INTERFACE.md`——**冻结**的检测器契约与全部裁定（R1–R14），包含那些被证据推翻后修正过的。
- `docs/CONTRACTS.md`——实现前的契约调研，每条结论都带**文件路径与行号**。
- `docs/DESIGN.md`——故障分类、触发条件、机制设计与实测后的修正。
- `docs/PROMPTS.md`——预防/纠正/拒绝三段文案。插件已不注入提示词，文本留作**手动选用**。
- `verify/REPORT.md`——独立验证报告，含查出的缺陷与修复。

### 7.4 验证期间查出的缺陷（这部分才是有用的）

其中两个只能靠**读源码**或**对抗性测试**发现，跑正常路径永远跑不出来。

| 编号 | 严重度 | 是什么 |
| --- | --- | --- |
| `D-0` | 高 | 注入消息用了已退休的 `source.kind = 'plugin'`，被 v4 会话格式**硬拒绝**（可能让会话不可读）。已改为"生产者自有"的 kind |
| `D-1` | 中上 | 截断判据**方向写反**：既漏报真截断，又误拦合法文档——**包括插件自己的 README**。已修，并补了能区分判据方向的用例 |
| `D-8` | 高（已接受） | `M5` 改不了冻结的请求 ⇒ 属**能力缺失**而非 bug。已移除接线、保留实现 |
| `D-10` | 高 | 检测器只认**裸标签**，认不出真实故障里的**带命名空间前缀**形态（`<antml:invoke>` / `<antml:parameter>`）→ `damaged=false` → M4 不触发、turn 静默关闭。已修（R14：结构分析跑在"去前缀的影子副本"上；不含冒号的文本返回同一字符串，零漂移）。**语料级验收（不变量，不是快照）**：把全部真实会话的每条文本**同时**跑修复前 / 修复后的检测器，差异恒为 **1 条**——正是用户实际撞到的那次 fork。绝对总数会随 append-only 日志持续增长（连验证过程本身都会写进去），故不作基线 |
| `D-5 / D-6 / D-7 / D-9` | 低 | 契约漂移、默认值里硬编码本机路径、发布件里留着诊断开关、以及自相矛盾的文档段落。全部修复 |

## 8. 已知边界

1. **治不了已经被带坏的对话**：改写历史需要可写接缝（`M5`，D-8）。绕法：新开会话，或一句话让模型忽略那段。
2. **不阻止第一次失败**：提示词层预防已按设计移除，第一次照样写坏，只是不再静默。
3. **有界扫描**：最多 200 个字符串叶子、深度 24；更深或更靠后的会漏检（有意为之，宁漏勿扰）。
4. **配置会被校验但没有 UI 表单**：用手写的 Standard Schema v1（以保持零依赖），管理器报 `unsupported`——校验生效，但不渲染表单。
5. **自愈触发时多一次模型请求**，由 `maxCorrectionsPerTurn` 限次。
6. **绝不碰真实工具调用**：只有**没有任何** `tool-call` 块的消息，才会被判定自愈或改写。

## 9. 仓库结构

```text
plugin/           可安装的 bundle（package.json + cordis.patch.yml + index.js + src/）
  src/detect.js   纯检测核心——不 import 任何 DSH 包，可在普通 node 下直接跑
  index.js        Host 接线：M2/M3/M4，每个监听器都 try/catch + effect 作用域注册
docs/             设计、冻结契约（R1–R12）、契约调研、提示词文案
tests/            182 条断言：V1/V2/V3 的 fixture + 反例 + 性质测试
verify/           独立验证：独立探针 + 复现脚本 + 报告
```

`plugin/` 是包本体，其余都是**证据**。
